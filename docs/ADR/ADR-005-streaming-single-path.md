# ADR-005 스트리밍 단일 경로, 행 제한은 setMaxRows

- 상태: 승인됨
- 날짜: 2026-11-15
- 구현: 계획 (Phase 1, 4, 5)

## 맥락

명세 10절은 대용량 조회와 추출을 요구한다. 결과를 모두 메모리에 올린 뒤 변환하면 힙이 결과 크기에 비례해 커진다.

## 결정

- 조회는 한 경로만 쓴다. `QueryExecutor` 는 행을 `RowConsumer` 콜백으로 넘기고 List 를 돌려주지 않는다. `ResultWriter` 는 컬럼 정보, 행, 종료 메타를 `OutputStream` 에 바로 쓴다.
- fetchSize 와 스트리밍 ResultSet 조건은 DB Provider 가 DB 마다 적용한다.
- 행 수 제한은 SQL 을 감싸는 재작성 대신 `Statement.setMaxRows(maxRows + 1)` 로 건다. 한 행을 더 받아 초과 여부를 안다.
- 응답은 첫 행을 받은 뒤 시작한다. 실행 전 오류는 정상적인 오류 응답이 되고, 스트리밍 도중의 실패는 HTTP 상태를 바꿀 수 없으므로 연결을 끊고 이력에 실패로 남긴다.

## 결과

- 힙 사용량이 결과 크기와 무관해진다. Phase 5 통과 기준은 제한된 힙(예: 256 MB)에서 10만 행 추출이다.
- 사용자 SQL 재작성을 피하므로 SQL Server 의 ORDER BY 제약에 걸리지 않는다.
- 도중 실패를 클라이언트가 상태 코드로 알 수 없다(설계 §11 4번). 이력과 끊긴 응답으로 알린다.
- DB 별 스트리밍 동작은 미실측이며 Phase 1 통합 테스트에서 실증한다.

## 근거

- 승인된 설계 §3.1, §6, §8 과 §10 의 ADR 005 (List 적재 금지, SQL 재작성 회피).
