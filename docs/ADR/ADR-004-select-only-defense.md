# ADR-004 SELECT 전용 3중 방어, 파싱 실패는 거부

- 상태: 승인됨
- 날짜: 2026-11-15
- 구현: 계획 (Phase 2)

## 맥락

명세 9절 1·2·3·5항은 SELECT 전용 실행, DML·DDL 차단, 허용된 SQL 만 실행, SQL Injection 방지를 요구한다. 명세는 「SQL 문자열 검사만으로 SELECT 전용 정책을 완벽하게 구현할 수 있다고 가정하지 않습니다.」라고 적는다.

## 결정

1. 저장할 때 SQL 파서(JSqlParser)로 단일 SELECT 문인지 검증한다. 파싱에 실패하면 거부한다.
2. 실행할 때 읽기 전용 트랜잭션을 건다. 수단은 DB 마다 다르다([DATABASE_SUPPORT.md](../DATABASE_SUPPORT.md)).
3. 읽기 전용 DB 계정을 권장하고, 연결 테스트에서 쓰기 권한이 보이면 경고한다.

- 저장되고 활성화된 SQL 만 실행한다.
- 파라미터는 PreparedStatement 바인딩으로만 넣는다. 문자열 치환은 금지한다.

## 결과

- 파서의 방언 커버리지가 위험이다(설계 §11 2번). 파싱 실패는 거부가 기본이고, DB 별 SQL 모음으로 테스트한다.
- SQL Server 는 읽기 전용을 트랜잭션으로 강제할 수 없다(설계 §11 3번). 계정 권한과 파서에 의존한다.
- Phase 2 통과 기준: 명세 12절 Parameter Test 7종, 인젝션 문자열이 값으로만 바인딩됨을 4개 DB 에서 확인, DML·DDL·다중문 거부.

## 근거

- 승인된 설계 §7 과 §10 의 ADR 004 (문자열 검사만으로는 부족하다, 명세 9절).
