# ADR-003 단일 디스패처와 메모리 라우트 레지스트리

- 상태: 승인됨
- 날짜: 2026-11-15
- 구현: 계획 (Phase 3, 4)

## 맥락

데이터 API 는 사용자가 등록·수정·비활성화하는 API 정의(명세 5절 ApiDefinition)로 정해진다. URL 과 SQL 을 코드에 고정할 수 없고, 수정은 즉시 반영돼야 한다.

## 결정

- `/api/v1/**` 를 받는 디스패처 컨트롤러 하나가 메모리의 `RouteRegistry` 에서 (HTTP Method, 경로)로 API 정의를 찾아 실행한다.
- Spring MVC 핸들러를 실행 중에 등록하거나 해제하지 않는다.
- API 정의가 바뀌면 레지스트리를 바로 갱신한다.
- 요청 한 건의 처리 순서: 라우트 조회 → 인증·권한 → 파라미터 검증·변환 → 동시성·속도 제한 → 쿼리 실행 → 스트리밍 출력 → 이력 기록.

## 결과

- 단순하고, 등록·수정이 바로 라우팅에 반영된다. Phase 3 통과 기준은 중복·예약 경로 거부와 수정 즉시 반영이다.
- 모든 데이터 API 가 한 핸들러를 지나므로 지표와 이력은 원시 URI 가 아니라 API 정의 단위로 모아야 한다([REQUIREMENTS.md](../REQUIREMENTS.md) AR-1 의 OM-4).
- 지금은 데이터 API 가 없다. `/admin/api/v1/runtime` 과 health 를 뺀 모든 경로는 404 `NOT_FOUND` 다.

## 근거

- 승인된 설계 §3.1, §5.2 와 §10 의 ADR 003 (핸들러 동적 등록보다 단순하고 즉시 반영된다).
